# v0.10.29 - honest headless refusals, a Chromium notice that is true, and help that speaks to an operator

### Fixed
- **Headless runs on Windows get the right refusal.** A NUL-device stdin is no
  longer mistaken for a terminal, so `roots grant` and `census grant` under a
  service, a scheduled task, or any wrapper that closes stdin exit 2 ("nothing
  here can ask you; pass `--yes`") instead of 1 ("the operator said no").
- **The Chromium notice is only made when Chromium can actually be installed.**
  On an install without the `[browser]` extra the daemon no longer announces a
  download it cannot run; it names the two-step remedy once. When the download
  does run, a failed install is reported with its exit code and log path.
- **`daemon status` names the vault root and the port's provenance in every
  verdict**, including Ready, on unwrapped lines.
- The audit root used by the inventory metrics and the daemon's operating home
  come from one definition for every vault layout, so `debug avoidable-ask`
  agrees with the daemon from any directory, including custom vault paths.

### Changed
- Every `--help` surface speaks to an operator: no internal ticket or section
  identifiers anywhere in the command tree, ASCII throughout, and `user set`
  describes what it does. A test walks the whole command tree so a new command
  cannot reintroduce them.
- `systemu start --help` names the dashboard extra.
- The dashboard-missing refusal and the inventory-hit line are ASCII.
- `systemu info` is titled as systemu.
