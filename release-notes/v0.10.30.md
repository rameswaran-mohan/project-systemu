# v0.10.30 - nothing that ships names a private place, and a Chromium probe that admits what it cannot tell

### Fixed
- **Every outbound User-Agent identifies the package by its PyPI page.** The
  web tools' and the geocoder's default User-Agent named a source-forge
  account; all three now read `systemu/<version> (+https://pypi.org/project/systemu)`,
  pinned on the real request path.
- **Nothing that ships names a private place or person.** Test text, a shipped
  prompt, a seed tool's example, and the setup prompts carried a development
  directory name, a worktree name, and sample profile data drawn from a real
  person and place; all of it is synthetic now, and a test over the shippable
  tree keeps it that way on both channels (its own output is redacted, so a
  failure never reprints what it found).
- **An unanswerable Chromium probe never authorises a download.** When the
  browser probe itself fails (a broken runtime dependency, a partial install),
  the daemon says it could not determine whether Chromium is installed, names
  the reason, and does not start or announce a download; before, any probe
  failure read as "not installed" and re-triggered the download on every start.
- `daemon status` prints the build line, including its package path, on one
  unwrapped line.

### Changed
- `daemon status` exit codes name the verdict: 0 Ready, 2 Starting, 1 Not
  running; documented in its help.
- The daemon's lifecycle verdict lines (ready, stopped, did not become ready)
  are ASCII, and so is every census consent card (all three categories and the
  unknown-category refusal).
