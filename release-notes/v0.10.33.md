# v0.10.33 - typed confirmation for money, a full privacy page, one Telegram gateway, and the MCP SDK on both major lines

### Changed
- **Money-moving and irreversible actions need a typed confirmation and are
  never remembered.** A card for a `money_move`, `local_delete` or other
  irreversible effect offers Deny or a typed "Approve once"; the phrase (the
  amount, or the tool name) is checked server-side. There is no "Always allow"
  for these effects, the decision store refuses a standing approval for them,
  and bulk approval and the phone lane refuse them. One typed approval runs
  the action once, even when two lanes hold the same card. Loosening the gate
  posture (`settings set gate_mode`, `decisions mode --set`, the Settings page)
  needs a typed `--confirm "<phrase>"` on every surface.
- **The MCP SDK dependency is `mcp>=1.23,<3`.** Both major lines work through
  one feature-detected seam; three places that silently misbehaved on 2.x
  are fixed. The full MCP test set passes on mcp 1.23, 1.30 and 2.3.
- `pywin32>=306` is declared on Windows: it is what encrypts secrets at rest,
  and it previously arrived only as a side effect of another dependency.
- The `anthropic` provider SDK is an optional extra (`systemu[anthropic]`, in
  `[all]`).

### Added
- **`systemu tools diff [TOOL] [--json] [--pending]`** shows what a tool
  change would grant before you approve it (exit 0 nothing new, 1 new
  capability, 2 error). A dependency card previews the full transitive
  install (`pip --dry-run --report`) on a worker thread and says so when it
  cannot, never guessing.
- **A tool's network hosts are part of what you approve.** A tool's
  declared hosts are bound into its approval; an approval granted before
  hosts were recorded asks once more for a networked tool. Dependency
  cards are one per requirement, with the bare package spec.
- **"Answered from your table" chips** on Work, the workflow detail page and
  chat, from a durable per-run record of which table rows a run consulted or
  supplied (names only, never values). The inventory-hit rate is computed
  from those records, and runs whose record cannot be read are reported as
  not evaluated instead of counting as zero.
- **Table health.** An item whose file or folder disappears is marked broken
  with a reason and a time and can be recovered; broken items show in Needs
  you and on /health. A health check runs every 10 minutes
  (`SYSTEMU_TABLE_HEALTH_MINUTES`, 1-1440). `unavailable` is a recognised item
  status.
- **Approval fatigue on /health:** cards created and resolved, resolution
  latency, standing grants, denies and bulk approvals.
- **Time to first task** on /insights, from the onboarding funnel stamps.
- The world-model digest says how many facts it did not show, and a run's
  summary cites what it checked and found absent.
- Windows installer inputs: a launcher and a vault that uninstall never
  removes.

### Fixed
- **/privacy names every place your data goes on a default install.** It names the relay that
  carries web search and page extraction, every configured MCP server (on
  this machine or remote), Telegram when it is configured, and the ledger
  export. It reads the live profile and runs no probe when it renders.
- **Secrets at rest.** The keyring backend reads `dpapi` only after a real
  encrypt/decrypt round trip (otherwise `wincred` or `plaintext_fallback`).
  Plaintext secret files are re-encrypted when the daemon starts. The new
  envelope is read back from disk and must decrypt to the original bytes
  before it replaces the file. The one-time backup is then deleted if it
  holds exactly those bytes. Any backup that remains is named by
  `systemu doctor`. /privacy and /health read the same verified row.
- **One Telegram gateway per process.** The dashboard no longer starts a
  second poller on the same bot token. `/answer <tag> <value>` works as the
  push message says. Free-text and choice questions record the answer by
  field, and choices are accepted by label, number or button. A harness's
  question for input is pushed to the phone.
- **Cancelling a run withdraws its parked cards.** This holds from the
  dashboard, from chat Stop, and when Stop lands while a card is being
  parked. An answer that arrives afterwards gets "That run was cancelled;
  this answer was not needed." on the dashboard (as information, not an
  error), the CLI (exit 0) and the phone. No reconciler or resume path
  restarts a cancelled run. A durable marker survives a daemon restart.
- **Provider readiness includes the provider's SDK.** A provider reads as
  ready only when its SDK imports. The
  welcome flow, recall and `doctor` name the missing package and the command
  that installs it. `doctor` reports a missing provider SDK only for a
  provider you configured.
- `systemu debug resolver-replay` works from an installed wheel: the corpus
  it replays now ships in the package.
- New effect tags start at the unknown band and cannot lower an existing
  tag's severity.
- Inbox decision summaries name the recorded choice and claim only what was
  persisted. Finish setup reads back what it saved. The `.env` the wizard
  writes is the operating home's, never the current directory's. A failed
  chat task says why and what to do next. Root refusals echo the path as
  typed.
- `daemon start` reports an already-serving daemon plainly and names the
  right remedy when the port is in use. `daemon status` names the port's
  provenance once. The remaining non-ASCII characters on start and refusal
  paths are ASCII.
- Rendering: the banner's process scan and the Ctrl+K index run off the
  render path, the dependency probe is answered once per distribution, and
  select popups are opaque.
