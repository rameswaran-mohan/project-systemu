# v0.10.34 - typed confirmation for MCP money, every approval shows what runs, and a verified/claimed label on every result

### Changed
- **A local or private MCP server must be allowed once.** Adding one in
  Settings asks "Allow systemu to connect to <host:port>?"; a saved server
  that is refused shows an "Allow <host:port>" button next to its reason.
  Servers listed in `SYSTEMU_MCP_SERVER_URLS` count as allowed for exactly
  their host and port.
- **Summaries run on the cheap model tier.** Memory consolidation,
  memory-candidate extraction and the episodic session summary move from
  tier 1 to tier 3. `SYSTEMU_PARSER_TIER=tier1` moves them back.
- New tier knobs: `SYSTEMU_REASONING_TIER`, `SYSTEMU_JUDGE_TIER`,
  `SYSTEMU_EXECUTOR_TIER`, `SYSTEMU_FORGE_TIER`, each defaulting to the tier
  its calls already used. With one model configured, every stage uses it.
- Numeric IP spellings that are not canonical (`2130706433`, `0177.0.0.1`)
  are refused by every network check.
- A terminal command that names no runnable command (blank, a NUL byte,
  or one that cannot be split) is refused instead of carded.

### Added
- **Every network connection to an MCP server is checked and pinned.**
  Listing, discovery, runtime connect and every tool call go through one
  resolve-then-check guard and connect to the address that was checked;
  redirects are checked the same way.
- **The ledger records the gate.** Effect rows carry the effect tags, the
  gate verdict, the decision that allowed them and where it was answered
  (dashboard, CLI, Telegram, policy); committed effects get their own rows;
  chat actions reach the ledger; a value that was not captured reads
  `not_recorded` with a reason.
- **More of your machine for the census, each with its own consent:**
  automation-capable apps, default file handlers and printers. Every
  category is granted from the CLI (`systemu census grant <category>`); the
  /table panel shows each one and withdraws, pauses or resumes it.
- Folder repair cards on /table show the exact `systemu roots grant` command.
- Every model call goes through a named stage in the routing table.
- **Every result shows whether it was verified.** One check decides
  "verified", "claimed" or "measured" for every outcome, and every screen
  shows it: Work, workflow detail, chat, Home, the status menu, Telegram,
  the CLI, the task API and the ledger export. A click opens the receipt:
  what was checked, how and when, with secrets masked. A run that stops
  part-way lists what it already did, each item labelled.
- **Tool selection scales.** The agent sees the most relevant tools in full
  and a one-line list of the rest, in a fixed order; a `find_tools` tool
  searches every tool you have and reports each one's state. Only enabled,
  ready tools can run.
- `systemu doctor` shows whether secrets are encrypted at rest.

### Fixed
- **systemu's own consent and settings commands can only be run by you.**
  The agent's command paths refuse every operator command (grant, revoke,
  settings, decision mode, resolve and the rest) in every spelling, wrapper
  and chain; a remembered approval never lets one through; the refusal
  names the command to run yourself.
- **MCP tools that move money or delete things get the same typed
  confirmation as built-in tools**, on every surface: never "Always allow",
  never bulk or phone approval. A server can raise a tool's risk through
  what it declares, never lower it. A call the gate refuses is refused, with
  a card to set the tool's risk category yourself.
- **Opening and closing applications is approved per application.** The app
  is identified before the approval check; an approval covers exactly that
  app; an app that cannot be identified unambiguously is refused; closing by
  process id is never remembered.
- **Every approval card shows exactly what the tool will receive.** Each
  call is fixed once before any approval check; the check, the card and the
  run all use that same value. Every parameter is listed, and every value is
  masked before it is shortened.
- **A typed approval for an MCP payment counts only for the run that asked,
  and only until the card expires** (30 minutes). Another run with identical
  details is refused and asks again; the run that stopped at the card can
  pick it up when run again.
- An action with no receipt reads "claimed" in the ledger export, not blank.
- **The terminal-command approval covers exactly the command that runs.**
  An approval can no longer be signed for one command while another runs.
- **No secret reaches a saved file or an outgoing message.** The event log,
  event bridge, prompt transcript, resume history, decision audit, dry-run
  replay, ledger rows and the log of phone replies are masked before they
  are written; outgoing notifications mask the credential after
  `Authorization: Bearer/Basic/Token` and passwords in URLs; summaries are
  masked before they are shortened.
- **A tool's declared credential name can never overwrite a setting** the
  runtime or the system relies on (PATH, proxies, Python and systemu
  settings, and the rest).
- An MCP server that cannot be listed reports a failure with the real
  reason ("connection refused by host:port") instead of zero tools. A call
  whose tool cannot be confirmed unchanged, or is no longer offered, is
  refused and nothing is sent.
- SQLite and Postgres vaults create the action-audit table (appends had
  been failing silently) and keep the gate stamp.
- A record-only shadow measurement reads "measured", never "verified".
- Receipts are stored under the operating home, not the current directory.
- Model validation's reachability check works.
