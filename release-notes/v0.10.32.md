# v0.10.32 - the MCP SDK pin, and a test workflow that runs

### Fixed
- **`pip install systemu` no longer resolves the 2.x MCP SDK.** The
  official `mcp` package released 2.0 on 2026-07-28 and removed the
  streamable-HTTP client (`mcp.client.streamable_http.streamablehttp_client`)
  that the remote-server transport imports, so a fresh install of any earlier
  release attached stdio and SSE servers fine but failed on the first
  streamable-HTTP server. The dependency is now `mcp>=1.0,<2` (verified
  against mcp 2.2.0); the port to the 2.x `Client`/`MCPServer` API is a
  separate change and the pin stays until its tests pass against 2.x.
- **The public `tests` workflow runs to completion.** Every run since the
  public tree was cut failed at collection, for reasons that never touched
  the shipped package: the repo-root `tools/` lint helpers were not on
  `sys.path` under bare `pytest` (the local gate runs `python -m pytest`,
  which differs), `tomllib` does not exist on Python 3.10, one leg installed
  a lockfile the tree does not carry, and the compose-render leg never
  installed the package it was collecting tests for. `pythonpath = ["."]`
  is pinned in the pytest configuration, `tomli` backs `tomllib` on 3.10,
  and the two legs install what they need.

### Notes
- No runtime behaviour changes beyond the dependency bound. Existing
  installs on mcp 1.x are unaffected; installs that already pulled mcp 2.x
  get 1.30.0 on upgrade.
